## 建议顺序

1. 重新确认小车固定、双轮悬空、供电和接线正常，先只启动APP。核对电压、两轮速度、距离及PID回读，保留日志；读取PID不应再触发参数写回。
2. 在主控页进行单方向短时输入，再松手；分别验证前后和转向。原摇杆需要接近外圈才发方向：本次手机布局的门槛约173px，150px拖动仍在中立区。其他布局不能照抄坐标，以实际界面及CMD3证据为准。
3. 同步核对APP实际写出与MCU实际收到的CMD3间隔、运动请求和超时状态。当前模块实际连接间隔90ms、latency4，HIGH请求未被接受；慢回调可能让运动间隔超过500ms。若出现安全停车或不连续，先分析时序，不延长MCU保护时间掩盖问题。
4. 验证松手、切换页面、进入后台、关闭手机蓝牙、模块断电和链路恢复。确认蓝牙运动请求及时清零、平衡输出规则保持、旧动作不恢复，重新操作需新的零指令使能。500ms是指令有效期，不是物理停车时间。
5. 联动边界通过后，再做连续30分钟遥测及队列/错误统计检查。另补原BLE模块搭配新APP＋新固件、权限拒绝、通知订阅失败、模块AT配置与断电保持等验收。

本轮约19分钟分段日志观察不等于30分钟完整捕获；150px触摸未产生非零CMD3，不能作为运动或松手停止通过的证据。已完成和失败过的版本、回退条件见[现场记录](HC05D_DEVICE_VALIDATION_20260924.md)及[配对矩阵](RELEASE_MATRIX.md)。
