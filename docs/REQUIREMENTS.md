## 每个新需求必须记录

- 稳定 ID、用户现象/目标、影响端、优先级、负责人或任务、状态。
- 明确范围及可观察的验收步骤；协议、设备安全、签名或数据兼容影响。
- 对应提交/PR、构建命令、APK/HEX 哈希、测试组合和证据路径。
- 未解决问题与下一步，及可执行的代码/应用/固件回退条件。

需求细化仍使用原 ID；新增缺陷保留 APP/KI 编号并关联需求。GitHub Issue 可以用于讨论，但这里保留当前需求摘要和链接，避免需求只留在聊天中。完成时同时更新状态和证据，不以勾选 PR 模板代替验证。
