# 20BC:5500 接收器记录

本记录对应 2026-09-17 在 Windows PC 上检查的 `VID=0x20BC`、`PID=0x5500`、`bcdDevice=0x1003` 接收器。结构化结果见 [20bc-5500-evidence.json](20bc-5500-evidence.json)。描述符和报文字段已读取，物理按键编号、左右摇杆对应关系以及 STM32 上的运行效果尚待实测。

## 只读证据

USB 配置描述符总长 84 字节，声明三个接口：

| USB 接口号 | 接口用途 | Class/Subclass/Protocol | 中断 IN | 最大包长 | 周期 | 声明的 HID 报告描述符长度 |
|---|---|---|---|---|---|---|
| `0` | Game Pad | `3/0/0` | `0x81` | 64 字节 | 10 ms | 123 字节 |
| `1` | Game Pad | `3/0/0` | `0x82` | 64 字节 | 10 ms | 123 字节 |
| `2` | 系统/用户控制集合 | `3/0/0` | `0x83` | 64 字节 | 10 ms | 101 字节 |

两个 Game Pad 顶层集合的 UsagePage/Usage 均为 `0x01/0x05`。Windows `HidP_GetCaps` 返回输入长度 10 字节、输出长度 5 字节、Feature 长度 0；所有输入字段的 Report ID 为 0。输入长度包含 Windows 补的零 ID 字节，实际 USB 输入为 **9 字节且无 Report ID**。[微软 HIDP_CAPS 定义](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidpi/ns-hidpi-_hidp_caps)

接口 `0`、`1` 各只读一包，Windows 缓冲均为：

```text
00 | 00 00 0F 80 80 80 80 00 00
```

分隔符左侧为 Windows 占位字节，不属于 USB 报文。HidP 解析得到 X/Y/Z/Rz 均为 128、Hat 为 15（Null）、无按键、另外两个 Simulation Controls 字段为 0。这是已读取的静态样本；没有以实际摇杆和按键操作确认每个字段的物理对应关系。

字段偏移通过 `HidP_GetUsageValue` / `HidP_GetUsages` 解析内存中的单 bit 合成报告交叉确认。这些合成报告没有发送到设备。输入只读取 UsagePage `1`、Usage `5` 的 Game Pad 集合，没有读取接口 `2` 的控制输入，也没有键盘采集、输出报告或 Feature 写入。

此证据保存了配置描述符的字段、Windows HID 能力和布局结果；123/101 字节是配置描述符声明的报告描述符长度，不代表本次保存了完整原始 HID 报告描述符字节流。

## 实际 USB 布局

| USB 字节/位 | HID 字段 | 大小/范围 |
|---|---|---|
| 字节 `0` bit `0..7` | Button Usage `1..8` | 每个 1 bit |
| 字节 `1` bit `0..6` | Button Usage `9..15` | 每个 1 bit |
| 字节 `2` bit `0..3` | Generic Desktop Hat，Usage `0x39` | 4 bit；逻辑值 `0..7`，支持 Null；样本为 `15` |
| 字节 `3` | Generic Desktop X，Usage `0x30` | 8 bit，`0..255` |
| 字节 `4` | Generic Desktop Y，Usage `0x31` | 8 bit，`0..255` |
| 字节 `5` | Generic Desktop Z，Usage `0x32` | 8 bit，`0..255` |
| 字节 `6` | Generic Desktop Rz，Usage `0x35` | 8 bit，`0..255` |
| 字节 `7` | Simulation Controls，Usage `0xC5` | 8 bit，`0..255` |
| 字节 `8` | Simulation Controls，Usage `0xC4` | 8 bit，`0..255` |

各数值字段 ReportCount 均为 1。按钮能力给出的 Usage 范围为 `1..15`，并由逐 bit 解析确认其位置；旧版 HID API 的按钮 `ReportCount` 区域是保留字段，本记录不使用该原始零值来判断按键数量。

## 固件采用的约定

`20BC:5500` 按型号进入专用配置，固定选择 **USB 接口号 0**，不是枚举顺序中的“第一个看起来像手柄的接口”。接口 `1` 不参与此次控制，接口 `2` 不用于游戏手柄输入。

X/Y 对应左摇杆，Z/Rz 对应右摇杆；这是待操作验证的配置约定。新 X 方向使用 `raw_x - 128`，Y 方向使用 `128 - raw_y`，四轴结果均夹到 `[-127, 127]`。Hat 的 `0/2/4/6` 分别映射上/右/下/左，奇数映射相邻斜向，`8..15` 按 Null 处理；本次样本中的中位值为 `15`。新配置方向位明确为 UP=`1`、RIGHT=`2`、DOWN=`4`、LEFT=`8`，中位为 `0`；legacy Hat 保留原算法，其位语义不由这份新设备证据推定。

按键暂按常见 DInput 编号把 Usage `5..12` 映射为 L1/R1/L2/R2/Select/Start/L3/R3。该映射尚未在实物上逐键确认；Usage `1..4/13..15` 不映射，避免未经确认的按键触发现有 PID/校准功能。后续逐键采样后在 `Firmware/Hiwonder/src/gamepad_report.c` 更新映射表。

64 字节是端点容量，9 字节才是此配置要求的输入长度；缓冲容量与报文字段长度分别处理。专用配置通过中断 IN 接收，跳过 `SET_PROTOCOL` 和启动 `GET_REPORT`，采用端点声明的 10 ms 轮询周期。实现及测试结果记录在 [开发记录](../DEVELOPMENT_LOG.md)。

调试观察量 `gamepad_raw_buttons` 保留原始按键位图，`gamepad_reports_accepted` / `gamepad_reports_rejected` 记录当前连接期间的解析计数，重新连接时清零。标定物理按键时可先定位原始 Usage，再决定是否开放或调整动作映射。

本次没有烧录。USB 断开/重连及无效包的状态清理，不等同于已经识别接收器仍在线时的无线手柄失联；无线状态、物理映射和整车控制结果均需后续验证。完整复测步骤见 [手柄兼容说明](../GAMEPAD_COMPATIBILITY.md)。
