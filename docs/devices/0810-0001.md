# Twin USB Joystick 0810:0001（2026-10-08）

**车端后续取证更新：** 用户确认从PC移到小车的是同一个新接收器。STM32实际枚举为 `20BC:5500/bcd1003`，接口0最大包8字节、周期5ms、report descriptor90字节；复位重新枚举后仍如此。此车端格式与下文PC的0810格式不同，也与此前暂停的20BC九字节格式不同。不能仅凭VID把实物认定为旧接收器；当前未确定两端枚举差异的原因。

车端格式将由独立八字节profile识别，选择条件同时要求20BC:5500/bcd1003、8字节端点和90字节报告描述符。下文保留PC阶段证据，车端实测映射及烧录结果见[现场记录](../releases/2026-10-08-twin0810-flash.md)。

关联 FW-HID-002。用户重新采购的一对 **2.4G** 手柄共用 USB 接收器；本次只使用其中一只，旧 20BC:5500 适配暂停。接收器直接插入小车 USB Host 使用，不涉及蓝牙模块或手机 APP 修改。

## 已取得的 PC 证据

Windows PnP 与目标限定的 SetupDi/HidD/HidP 读取确认如下。未发送输出/Feature 报告，未更换 USB 驱动。

| 字段 | 实测值 |
|---|---|
| VID / PID / bcdDevice | `0810 / 0001 / 0206` |
| USB 配置长度 / 接口数 | 34 字节 / 1 |
| 接口号 / alternate | `0 / 0` |
| class / subclass / protocol | `3 / 0 / 0`，非 Boot HID |
| interrupt IN | `0x81`，最大包长 8 字节，bInterval=2 ms |
| HID report descriptor 长度 | 202 字节 |
| 顶层集合 | 两个 Generic Desktop Joystick；Report ID 分别为 `1`、`2` |
| USB 输入长度 | 含非零 Report ID，共 8 字节；Windows 无需额外删除零前缀 |
| 中位样本 | `01 80 80 80 80 0F 00 00` / `02 80 80 80 80 0F 00 00` |

两份 Windows collection 共用接口和端点，不能按两个 USB 接口处理。10秒中位采集读取 ID1=2500 帧、ID2=2501 帧；120秒采集各约30000帧。静止仍连续上报，所选通道约4ms一帧。实测用户操作只使 ID1 变化，ID2 保持中位，因此本次固定选择 ID1，不在运行中自动切换。

## 报文字段

HidP 对保存的样本及逐 bit 合成内存缓冲解析确认字段位置；USB字节偏移从0开始。这项验证不等于每个物理键已经标定。

| 字节 | 描述符字段 | 本次解释 |
|---|---|---|
| `0` | Report ID | 选择1，合法通道2忽略 |
| `1` | Generic Desktop Z，8 bit | 原生右X；当前实物一直128，超出死区时仍优先使用 |
| `2` | Generic Desktop Rz，8 bit | 原生右Y；当前实物一直128 |
| `3` | Generic Desktop X，8 bit | 左摇杆X；向右实测为255 |
| `4` | Generic Desktop Y，8 bit | 左摇杆Y；向前实测为0 |
| `5` 低4 bit | Hat，0..7，HasNull | 0=上，顺时针八向；8..15中位，实测15 |
| `5` 高4 bit | Button Usages 1..4 | Usage2为右杆向右/右面键，Usage4为右杆向左/左面键；合成数字转向，不触发PID/机械中点修改 |
| `6` | Button Usages 5..12 | Usage5..10已逐键核验；11/12未专项标定，现有控制无对应动作 |
| `7` | Vendor Page FF00 Usage1，8 bit | 含义未确认，不作无线在线/模式标志 |

轴中位128，X=`raw-128`，Y=`128-raw`，输出钳位到[-127,127]。原控制函数使用ly前后、rx转向，死区10。

MODE短按及长按约3秒后，右摇杆仍表现为面键位，byte1/2持续128。用户反馈长按时灯熄灭；本次没有取得原生右模拟轴输出，也没有向厂商Output字段发送猜测命令。

用户明确选择保留左杆前后/右杆转向，并接受数字转向及对应面键同效。最终策略：原生右X绝对值大于10时优先使用；否则Usage2输出rx=+127，Usage4输出rx=-127，两者同时按或均未按时rx=0。右杆上下不产生转向。转向幅度由现有转向档位决定，不能宣称当前实物具有右杆比例转向。原生lx/ly/ry仍按描述符解码。

## 逐项物理标定

本地输入监测页面逐项提示动作，用户每次保持后松开并记录。12项均取得稳定样本，单项主样本815～1535帧。右杆和面键完整8字节报告相同，未发现可区分来源的vendor字段。

| 物理操作 | 实测USB输入 | 固件含义 |
|---|---|---|
| 左杆前 | `01 80 80 80 00 0F 00 00` | ly=+127，前进请求 |
| 左杆后 | `01 80 80 80 FF 0F 00 00` | ly=-127，后退请求 |
| 右杆左 / 左面键 | `01 80 80 80 80 8F 00 00` | rx=-127，左转请求 |
| 右杆右 / 右面键 | `01 80 80 80 80 2F 00 00` | rx=+127，右转请求 |
| L1 | `01 80 80 80 80 0F 01 00` | Usage5，增加前后速度档 |
| L2 | `01 80 80 80 80 0F 04 00` | Usage7，降低前后速度档 |
| R1 | `01 80 80 80 80 0F 02 00` | Usage6，增加转向档 |
| R2 | `01 80 80 80 80 0F 08 00` | Usage8，降低转向档 |
| START | `01 80 80 80 80 0F 20 00` | Usage10，沿用现有提示音动作 |
| SELECT | `01 80 80 80 80 0F 10 00` | Usage9，当前控制无动作 |

这些是PC物理输入与源码控制请求的对应，不代表车轮物理方向或实车速度已经核验。速度档范围1..5、初值3；转向档范围1..5、初值2，均沿用现有控制。START不是急停键。

## 验收范围与原始材料

### 车端八字节输入

其报告无Report ID：byte0/1为15个按键和1个填充位；byte2低四位为Hat；byte3/4为X/Y；byte5/6描述符名为Z/Rz；byte7为各四位C5/C4。用户按序操作后，实际右杆左右改变的是byte6（Rz），故车端rx使用 `byte6-128`，ry使用 `128-byte5`；不能只依据Z/Rz名称照搬物理左右映射。车端直接用轴值转向，面键不合成数字转向，也不修改PID。PC0810分支保留用户此前接受的数字转向策略。

| 车端物理动作 | 实测8字节USB输入 |
|---|---|
| 回中 | `00 00 0F 80 80 80 80 00` |
| 左杆后 | `00 00 0F 80 FF 80 80 00` |
| 右杆左 | `00 00 0F 80 80 80 00 00` |
| 右杆右 | `00 00 0F 80 80 80 FF 00` |

接口0报告随用户这一只手柄操作变化；接口1不打开、不自动切换。八字节profile单独启用500ms有效报告失效清零，原九字节20BC路径保持。

关机专项：用户按要求推住左杆前进后关闭手柄，确认关机才松杆，并回复“已关机”。PC采集从前进报告回到 `01 80 80 80 80 0F 00 00`；在用户确认关机后的两次快照间约5秒内，ID1继续收到1228帧中位报告，ID2继续中位，未保持旧前进值。这确认本次关机场景接收器归中；没有精确标记断电瞬间，不能量化无线停车延迟或外推到全部射频干扰/超距场景。

本地原始材料在本工作区忽略目录 `build/twin-0810/`：设备/配置二进制、能力与逐bit布局JSON、带时刻的原始输入采集。记录中不公开完整设备路径、手机序列号或蓝牙地址。

主机测试须验证严格8字节/ID、正确轴和按键、ID2不覆盖或清空ID1、不替ID1续期、损坏包/重连清零、500ms边界和USB毫秒计时回绕。无报告清零仅针对已测为周期上报的0810设备；不能识别接收器持续重复旧非零数据的无线失联，仍须物理断电测试。
