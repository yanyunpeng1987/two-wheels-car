# MVTBOT module

- Read README.md and docs/HANDOFF.md before working on the app. Firmware collaboration entry points are in docs/PROTOCOL_COORDINATION.md.
- project/ is the current v21 Apktool rebuild input (raw DEX + resources), not original Java/Kotlin source. materials/analysis/jadx-reference has 103 known decompilation errors; do not treat it as a buildable source project.
- The immutable v21 input is 2.3.6-mvtbot.2, with original Wonderbot business DEX. Current release is installed v40 / 2.3.6-mvtbot.13-hc05d with APP-UI-004 dynamic Contact version display, preserving APP-UI-001, Bluetooth logic, and MCU pairing. First open and reopen were visually verified on the phone with intact company/website and no duplicate row or fatal/UI error. See ../../docs/APP_VERSION_INFO_20260928.md. Preserve v39 permission/communication evidence in ../../docs/HC05D_DEPLOYMENT_20260928.md and older records; user-reported Bluetooth stability has no specified duration and does not replace controlled-motion acceptance. Historical NUL origin is still unproven.
- Preserve raw crash evidence. C0 80 in the captured Android JNI logs represents one Java NUL in Modified UTF-8; it is not proof that the BLE wire contained C0 80.
- Use tools/Build-MVTBOT.ps1 for local packaging. It does not install an APK. Device installation, BLE interaction and firmware flashing are separate actions that must follow the user's current scope and target selection.
- Startup auto-connect was removed completely in v38: no DebugAutoConnect class, target asset, or build option. Do not restore it through an old diagnostic command. ManualBleScanner owns one user-triggered Mini picker scan with bounded duration/cooldown, stale-callback rejection, and connection/lifecycle cleanup; preserve those contracts and verify manual connection on the phone before claiming acceptance.
- v39 introduced the retained ManualBlePermissions gate: Android 12+ checks only SCAN/CONNECT, Android 6-11 requires Fine location, and requests contain only missing permissions. A request always returns false for that click; permission completion never auto-scans. The fixed Mini UI skips startup permission requests, while other robot routes retain legacy behavior. Keep genuine background scan/motion cleanup. UI-only rollback code 41 is an unbuilt parameter default.
- AppVersionUi reads installed PackageInfo; never hardcode displayed version strings. It is compiled with the real Android SDK/full APK and checked visually on the phone. Existing host transport_sources() excludes only this independent UI helper; all communication sources remain in the transport regression suites.
- Build-MVTBOT.ps1 defaults to the LINK-001 business build: verify immutable v21, decode and patch primary smali in an output snapshot, compile Java/D8 auxiliary DEX, then verify the final APK and bridge signatures. Preserve raw classes2/3. Never modify canonical project/ to implement logic. -BaselineOnly and -RollbackUiOnly explicitly build the old logic.
- Signing keys and the DPAPI password remain in the user's LOCALAPPDATA/Android/Signing/MVTBOT directory. Never copy, print, archive or commit private signing material.
- materials/, project/, build/ and validation/ stay local under the repository policy for original packages, device evidence and generated artifacts. Git maintains documentation, reusable scripts, owned branding, baseline/project-files.json and changes/README.md. Never add APKs, complete decompiled sources, local import metadata or signing secrets to Git.
- Follow changes/README.md when beginning any resource or logic edits so changes in ignored project/ are captured as explicit patches/versioned inputs. The v21 baseline records hashes only; it is immutable history, not recoverable source or a replacement for the full archive.
- New Git clones/worktrees omit those local directories. Run python tools/verify_android.py from the repository root for repository-only checks. Restore the full archive before APK work, then use --project-root Android/MVTBOT/project and the import verifier. Missing local artifacts do not mean an empty Android source project. Intentional changes fail import-baseline verification; preserve and version them instead of overwriting files to pass.
- Preserve any other task's changes in Firmware/ and shared project documents. No app packaging task implies permission to change the motor-control firmware.
