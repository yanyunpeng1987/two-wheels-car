# 自稳倒下现场记录：右编码器突跳触发SPD

日期：2026-09-28；关联FW-STOP-001、KI-004。用户报告小车在无人干扰的平衡状态下倒下，随后确认电机已停止并暂时保持供电。

先用指定ST-LINK、HOTPLUG只读保存全部64KiB RAM、核心故障/运行状态及Flash寄存器，再保存完整128KiB Flash和TIM2/TIM3配置。没有halt、reset、run、写内存、改PID或烧录。证据目录为本地 `build/fall-diagnostics/20260928-121427/`，实物UID与此前板卡一致。

## 已验证与仍待确定

实际TIM2的CCMR1=`0xF1F1`、SMCR=3、CCER=`0x11`；TIM3的CCMR1=`0xA1A1`、SMCR=3、CCER=`0x11`。此前右侧滤波增强确实仍在，异常仍复现；不能称T3/T4已经消除KI-004。

实际构建的右编码器引脚为PA1（A/TIM2_CH2）和PA5（B/TIM2_CH1），源码配置AF1和上拉；SWD为PA13/PA14，CCD为PA15/PB3/PC0。本工程没有把PA15/PB3的可选TIM2功能用于编码器，也未启用PA5的可选SPI1功能，不能把替代功能表当作实际复用冲突证据。尚未读取现场GPIOA MODER/AFRL，AF1为程序配置依据；电气耦合或地回路影响仍待验证。

已确认保护动作依据是右计数突跳，但编码器本体、A/B线束与接头、供电/地回路、干扰或定时器输入状态等具体来源尚未定位。触发帧的电压正常不排除更短的电源/地弹事件：电池监测累计仍有低读数与范围错误，需与编码器波形同步核对，不能据此单独认定供电为根因。

该跟踪器冻结的是本次启动/显式清理后的**第一次**停输出事件，自动放下重新使能不清旧记录；DWT约51秒回绕，不能仅凭cycles还原绝对时间。因此报告严格描述保存的首个停机事件，与用户当前倒下对应关系须结合此前操作记录，不能忽略已有更早停机的可能。

## 现场处理与后续

RAM、Flash及定时器证据已保存后，已告知用户暂不恢复自平衡运行，可以先断电再扶正并固定，避免扶正时自动重新使能。未要求用户带着故障继续运行，也未远程改变控制状态。

下一步优先核查右编码器A/B信号、供电及地回路，并与实际计数突跳同步取证；若需软件改动，独立设计对异常计数的识别与保护回归，不直接放宽SPD门限或取消保护。继续保持既有Flash启动修复、PID及电机映射。
