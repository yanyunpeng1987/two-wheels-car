## 屏幕与 RAM 证据

第一行 `Flag_move:0/1 T1` 标识这一轮固件。正常运行沿用原数据显示。
第一次实际输出门控从允许变为禁止时，冻结当时及此前最多 64 次采样，
后续倒地冲击或自动放下重启不会覆盖首因。PWM 恰好等于 0 不算停机。

| 屏幕 Stop 值 | 含义 |
|---|---|
| ACC | 连续 Z 加速度超限 |
| SPD | 原有双轮速度和门限触发 |
| KEY | 按键长按停机 |
| ANG | 倾角超过 ±80°，可能尚未清除 flag_move |
| MIX | 同一次控制处理有多个原因，需读 RAM 中的 reason_mask |
| UNK | 门控确实关闭，但没有匹配已知原因 |

停机后 `A`、`Z`、`dt`、`L@stop`、`R@stop`、`V@stop` 显示冻结数据，
其中 `dt` 是两次编码器读取间隔，单位 ms；A 为角度，Z 为 g，轮速为 cm/s。
第一行 flag_move 和第二行 Mode 仍是实时值。自动重启后旧证据仍保留；
正常情况下长按从停止切换为运行时清除证据，开始新一轮。
若同轮先有保护、后被按键重新使能，则保留首因跟踪状态。

Keil 可观察全局 `control_stop_trace`：`frozen`、`trigger`、`count`、
`write_index` 和 `samples[64]`。`write_index` 是下一写槽；满环最旧样本从
此槽开始。reason_mask 位值为 ACC=1、SPD=2、KEY=4、ANG=8、UNKNOWN=16。
RAM 还保存编码器原始计数、本轮 IMU 成功标志、按键电平和最终 PWM。
RAM 不写 Flash，掉电或复位会丢失；需要抓取时先固定车辆，避免调试暂停
本身使车跌倒。显示复制仅短暂屏蔽中断，字符串格式化在主循环完成。

## 第一轮实车顺序

1. 下载前固定车体、使驱动轮离地，确认使用刚验收的电机线序。
2. 下载后确认屏幕出现 T1，检查长按启停与保护停机。再开始地面测试。
3. 先在同一平坦场地做静止自稳，记录持续时间与是否突然停机；时间至少
   覆盖原来常见故障窗口，不凭短时间未复现认定修复。
4. 再用原来会触发问题的运动方式复测，记录 Stop、Z、dt、L/R、V；
   停机后先记录这些值，再进行下一次手动启动。
5. 在车体有支撑、车轮可自由转动的条件下确认实际拿起后仍能及时停机。
   20 ms 仅是加速度分支的软件确认时间，不等于实测总停机延迟。

若出现保护停机不及时、明显异常加速或无法安全继续，应结束测试并按当前受控回退方案处理；不要直接回刷本页后述含启动缺陷的历史基线。
以上是T1当时的测试顺序。实际T2先修启动完整性，T3加强右编码器硬件滤波，T4优化电压检测；这些结果和用户验收见后续记录。
